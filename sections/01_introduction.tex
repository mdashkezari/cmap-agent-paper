Marine and environmental research increasingly relies on integrating heterogeneous observations and model products across space and time.
Even when powerful data portals and programmatic APIs exist, the ``last-mile'' barrier often remains: scientists must discover appropriate datasets,
resolve identifiers, construct queries, and assemble analyses across multiple systems.

Recent advances in large language models (LLMs) suggest a complementary approach to closing this last-mile gap.
Retrieval-augmented generation improves grounding and factuality by coupling generation with an explicit, updateable external memory \citep{Lewis2020RAG},
while reasoning--acting loops enable verifiable computation by interleaving generation with calls to external tools \citep{Yao2022ReAct,Karpas2022MRKL}.
Together, these ideas make it possible to build natural-language interfaces that translate scientific intent into a sequence of validated, tool-executed operations rather than free-form prose, and that return concrete, inspectable artifacts back to the user.

The Simons Collaborative Marine Atlas Project (CMAP) is a curated data system designed to reduce these barriers by harmonizing diverse ocean and atmospheric datasets into a common data and metadata structure and indexing entries by location and time \citep{Ashkezari2021SimonsCMAP}.
Beyond raw data retrieval, CMAP exposes a suite of analytic primitives---spatiotemporal subsetting, climatological aggregation, depth profiling, and colocalization across in-situ and gridded products---through an interactive web portal and the open-source \texttt{pycmap} SDK.
Although these interfaces are powerful, users still face recurring frictions when working with a large harmonized catalog: (i) discovering relevant datasets across hundreds of products, (ii) resolving the exact table and variable identifiers expected by the SDK, and (iii) assembling multi-step workflows (e.g., retrieve $\rightarrow$ visualize $\rightarrow$ integrate $\rightarrow$ analyze) without manually orchestrating every intermediate command.

An enabling condition for agentic analysis is that CMAP is a curated platform: datasets and metadata are vetted and harmonized by domain scientists, with stable identifiers and standardized descriptors.
This allows \cmapagent\ to use retrieval and tool execution as mechanisms for grounding---resolving scientific intent to catalog-backed dataset/variable definitions and producing verifiable artifacts---rather than relying on a model's latent knowledge alone.
In practice, this means a researcher can ask a question in their own scientific language and receive an answer that is anchored to specific, named datasets in the catalog, executed by validated routines, and accompanied by the data files, figures, and code that produced it.

Here we focus on \cmapagent, an agentic layer built to support CMAP workflows through a natural-language interface that executes validated operations and produces scientific artifacts.

\paragraph{Contributions.}
The paper emphasizes contributions specific to the agentic system (not the underlying \cmap\ portal):
\begin{enumerate}[leftmargin=*]
  \item A domain-oriented architecture for grounded, tool-augmented analysis of ocean and environmental data, integrating semantic catalog retrieval with validated computational tools.
  \item A capability suite that operationalizes common CMAP workflows (dataset discovery, spatiotemporal subsetting, visualization, and colocalization) with artifact-centric outputs.
  \item A reproducibility model that combines provenance records, downloadable artifacts, and optional executable SDK code to bridge conversational exploration and scripted analysis.
  \item An evaluation plan aligned with emerging benchmarks for tool-using and data analysis agents \citep{Zhang2024DSEval,Li2025IDABench}.
\end{enumerate}
